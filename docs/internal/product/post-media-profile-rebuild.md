# 帖子媒体流和个人主页重构计划

本文承接用户关于“帖子预览、详情页图片播放器、正文中间插入图集、个人主页排版”的决策。它是下一轮实现前的产品和交互规划，不是完成证明。

相关后端目标合同必须同步到根目录 `backend-api-needs.md`。本文只描述前端产品目标、页面规则和验收口径；后端字段、校验规则和接口建议以 `backend-api-needs.md` 为协作入口。

## 本轮决策状态

本文是实现前的规划冻结稿。当前要求是先把产品规则、前端边界和后端协议需求写清楚，不在本轮继续扩大实现改动。

已确认决策：

- 正文媒体的 canonical 写入形态先采用 Markdown marker：单图用 `nexus-attachment:`，多图轮播用 `nexus-gallery:`。
- `content_refs` 继续作为扁平资源引用列表；它不能单独表达图集分组。后端如需更稳定的读取模型，可以后续补充只读或派生的 `content_blocks`。
- 旧帖子不做迁移兼容：只有附件但正文没有媒体 marker 的历史内容，后续会删除，不为它保留额外正文外图集逻辑。
- 实现目标是一轮完整体验闭环，而不是分阶段只做一半；写作器、列表页、详情页、lightbox、移动端和个人主页都要按同一套规则验收。
- 前端不伪造后端没有的字段：没有 `medium_url`、`original_url`、帖子标题、社区摘要或评论 permalink 时，只做明确降级，不假装能力已完成。

一次性交付的验收面：

- 写作器：单图插入、多图默认插入轮播、删除 marker 后不提交对应附件。
- 列表页：只展示正文第一个媒体块；外链播放器、单图、图集、普通链接按固定优先级降级。
- 详情页：媒体按正文顺序出现在主栏中间，长图默认限高，点击进入 lightbox。
- Lightbox：完整查看、缩放、拖拽、多图切换、移动端手势和打开原图入口。
- 个人主页：Twitter / X 式主栏内容流、帖子 / 评论 tab、Reddit 式右侧上下文栏、评论所在帖子和社区上下文。
- 验证：静态脚本、类型检查、内容边界检查、桌面和移动端浏览器 QA。

## 总原则

- 帖子和评论正文继续使用安全 Reddit-style Markdown，不保存用户 HTML。
- 附件只是资产，保存 URL、尺寸、文件大小、MIME、状态和说明；正文决定媒体出现的位置、顺序和分组。
- 详情页媒体属于正文主栏内容，按作者排版出现在文字中间，不统一堆在正文底部，也不放到右侧栏。
- 列表页只展示正文里的第一个媒体块作为帖子预览，不能把整篇正文的图片全部铺开。
- 旧帖子如果只有已绑定附件但正文没有媒体 marker，不做兼容追加。用户已确认旧内容后续会删掉。
- 白名单外链播放器和图片一样，是正文媒体块。普通网页链接预览只在正文没有媒体块时作为卡片预览。
- 实现时按一次完整体验交付，覆盖写作器、列表页、详情页、lightbox、移动端和静态检查；不要只完成其中一块就声明完成。
- 不新增 UI 库，不开放任意 iframe，不在前端伪造后端没有的缩略图、原图、统计或上下文字段。

## 正文媒体块模型

正文可以形成这样的内容流：

```text
文字
图片 1/2/3 轮播播放器
文字
图片 4
图片 5
文字
图片 6/7 轮播播放器
文字
白名单外链播放器
```

首选正文表示：

```text
单图：![图片说明](nexus-attachment:<attachment_id>)
轮播：![图集说明](nexus-gallery:<attachment_id>,<attachment_id>,<attachment_id>)
播放器：正文中的白名单 canonical 外链，或后端结构化 embed ref
```

前端规则：

- 写作器上传一张图片时插入单图块。
- 写作器一次选择多张图片时，默认插入一个轮播块。
- 后续可以支持选中多张已上传图片后合并为轮播，或把轮播拆成单图，但首个实现必须先覆盖“批量上传成轮播”。
- 评论继续按更克制的图片能力处理。如果后端和产品仍限制评论 1 张图，评论写作器不展示轮播插入能力。
- 删除正文里的 marker 后，这张图片或这组图片不再随正文发布或展示。
- 只绑定了附件但正文没有 marker 的内容，不进入详情页或列表页媒体展示。

## 帖子列表预览

列表页目标是扫读，不是完整阅读。规则固定为：

1. 从正文中提取第一个媒体块。
2. 如果第一个媒体块是白名单播放器，帖子卡片直接展示受控播放器预览。
3. 如果第一个媒体块是单图或图片轮播，帖子卡片展示受限高度的图片预览器。
4. 如果正文没有媒体块，再回退普通链接预览。
5. 如果没有媒体块和链接预览，再展示文字摘要。

列表页不得因为后端返回了 `attachments` 就追加图片。只有正文 marker 或后端结构化 block 能决定媒体是否出现在帖子预览里。

### 图片比例分流

设：

```ts
const ratio = width / height;
```

| 类型 | 条件 | 列表页处理 | 详情页处理 |
| --- | --- | --- | --- |
| 普通图 | `0.6 <= ratio <= 2.2` | 正常预览，限制最大高度 | 按内容列宽显示 |
| 长图 / 截图 | `ratio < 0.6` | 裁成 `4:5` 或 `3:4`，标记“长图” | 默认限高，允许展开或进入 lightbox |
| 超宽图 | `ratio > 2.2` | `16:9` 或 `21:9` 容器，`contain` 展示 | 按宽度完整显示 |
| 小图 | 宽或高 `< 300px` | 不强行拉满，居中显示 | 原尺寸或适度放大 |
| 超大文件 | `> 10MB` 到 `20MB` 量级 | 不直接加载原图 | 上传侧由后端压缩或拒绝 |

列表页固定口径：

- 桌面最大高度 `420px`。
- 移动端最大高度 `320px`。
- 长图在角标显示“长图 / 点击查看完整图片”。
- 超宽图优先 `object-fit: contain`，背景使用深色承托，避免裁掉中间内容。
- 多图最多直接展示 4 张，第 4 张显示 `+N`。
- 有 `thumbnail_url` 时列表页优先用缩略图，不能优先加载原图。

## 帖子详情媒体

详情页目标是尊重作者排版，同时保护阅读节奏。

规则：

- 媒体块在正文主栏中间，跟随 Markdown 顺序渲染。
- 单图在内容列宽内显示。
- 图片轮播块渲染为稳定播放器，包含上一张、下一张、当前序号和缩略导航。
- 普通图可以自然显示，但仍不能造成横向溢出。
- 长图默认最大高度 `80vh`，提供“展开长图”或进入 lightbox。
- 超宽图按内容宽度完整显示，必要时使用深色背景承托。
- 小图不强行铺满详情主栏。
- 白名单外链 canonical URL 在当前位置渲染受控播放器。
- 普通网页链接保持安全链接或后端链接预览，不变成任意 iframe。

详情页不再使用“正文上方或下方统一图片附件区”。如果图片没有插入正文，就不展示。

## Lightbox

Lightbox 是完整查看场景，不受列表裁切和详情页限高影响。

必须支持：

- 多图左右切换。
- 键盘方向键切换。
- `Esc` 关闭。
- 点击或按钮关闭。
- 缩放。
- 拖拽平移。
- 移动端滑动切换。
- 移动端双指缩放。
- 显示当前序号、图片说明和打开原图入口。
- 优先使用 `original_url`；没有时回退 `url`。

列表页和详情页的裁切规则只负责保护信息流和阅读体验；lightbox 负责完整查看长图、超宽图、小图和原图。

## 个人主页目标

个人主页不再把“帖子”和“评论”做成两个突兀按钮。目标结构是：

```text
主栏：Twitter / X 式用户时间线
右栏：Reddit 式上下文栏
```

路由：

```text
/users/[username]
/users/[username]/posts
/users/[username]/comments
```

主栏规则：

- 顶部是用户身份区：头像、昵称、用户名、签名、简介和公开角色。
- 资料摘要紧凑，不做营销型 profile card。
- 帖子 / 评论是同一主页语境下的 tab 或 segmented navigation，当前 tab 高亮。
- 用户帖子流复用全站帖子卡片规则，包括正文首个媒体块预览、播放器预览、图片比例分流、投票、评论数和来源记录。
- 用户评论流按时间线展示评论正文，不把短 `post_id` 当作正文内容。
- 每条评论必须展示所在帖子、所在社区和进入原帖的稳定入口。
- 未登录用户可以看公开主页、公开帖子和公开评论；写动作在动作处引导登录。

右侧栏规则：

- `关于`：头像、昵称、用户名、签名、简介和公开角色。
- `公开统计`：帖子数、评论数、收到的公开互动计数；没有后端字段就不展示。
- `常发社区`：用户公开发帖或评论过的社区摘要；没有后端字段就不展示。
- `内容入口`：只展示后端已支持且权限允许的入口。
- 不展示私密邮箱、后台权限细节、封禁原因、私密社区成员关系或未确认统计。

移动端规则：

- 单列优先。
- 用户身份区、tab 和内容流优先。
- 右侧栏内容下沉到内容流下方。
- tab 必须粘住主页语境，不要变成孤立按钮列表。

## 后端依赖摘要

后端协议写入根目录 `backend-api-needs.md`，本节只保留前端依赖摘要：

- 图片资产需要 `thumbnail_url`、`medium_url`、`original_url`、`width`、`height`、`size_bytes`、`mime_type`、`alt_text` 和 `status`。
- 后端需要保留或校验正文里的 `nexus-attachment:` 和 `nexus-gallery:` marker，或返回等价 `content_blocks`。
- 列表页如由后端返回 `preview.kind=media_block`，它必须来自正文第一个媒体块，不得来自孤立附件。
- 白名单 embed 需要后端 resolve、短链展开、provider、canonical URL、审核状态和可选标题 / 封面。
- 用户主页评论列表至少需要评论正文、所在帖子标题、所在社区摘要和 permalink。
- 用户主页右侧栏需要公开统计、公开角色、徽章和常发社区等字段；没有字段时前端不伪造。

## 验收口径

实现完成后至少验证：

- 发帖页可以插入单图和多图轮播。
- 详情页能按“文字 / 图集 / 文字 / 单图 / 文字 / 图集”的顺序渲染。
- 列表页只展示第一个媒体块。
- 外链播放器作为第一个媒体块时，列表页展示播放器预览。
- 普通链接只有在没有媒体块时才作为主预览。
- 长图不会撑爆列表页。
- 详情页长图默认不把页面拖成几十屏。
- Lightbox 能完整查看长图、超宽图和多图轮播。
- 用户主页帖子 tab 复用统一帖子预览。
- 用户主页评论 tab 展示评论正文、所在帖子和社区上下文。
- 桌面和移动端没有横向溢出。
- 控制台没有应用侧 error。

实现任务至少运行：

```powershell
npm run lint
npm run typecheck
npm run check:content-boundary
npm run check:content-segments
npm run check:api-boundary
npm run check:actions
```

涉及完整页面后再运行：

```powershell
npm run check:static
```

浏览器 QA 必须覆盖桌面和移动端，不用脚本结果替代真实页面判断。
