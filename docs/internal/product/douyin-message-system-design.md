# 抖音式私信系统设计

本文是 `cumt-nexus-web` 私信系统的产品、交互、视觉和接口落地规格。它以后端已补齐的私信合同为基础，以用户提供的抖音 PC 私信截图作为界面骨架参考：两栏会话、左侧搜索和会话列表、右侧聊天线程、底部输入栏。目标是对齐公开可观察的产品行为和信息结构，不复制第三方代码、图标、品牌素材或专有视觉资产。

## 1. 结论

私信不是消息中心、不是邮箱、不是后台工单，也不是通知 Bell 的一部分。首屏必须直接是可聊天的两栏界面：

- 左侧：搜索框 + 会话列表。
- 右侧：当前会话的聊天窗口。
- 没有 `全部 / 朋友 / 陌生人 / 归档` 这种顶部 tabs。
- 没有独立“收件箱式”筛选栏。
- 没有用户可见“已读”状态。
- 没有语音、视频、通话入口。
- 归档、拉黑、举报、免打扰等管理动作藏在会话更多菜单，不做成主界面常驻控制。
- 陌生人请求必须区分“别人发给我”和“我发给别人”：只有收件人能接受或忽略，发起人永远不能看到接受/忽略自己的请求。

## 2. 范围

### 必做

- `/messages`：私信主界面，桌面端为两栏聊天布局。
- `/messages/[conversationId]`：同一套布局，直接选中指定会话。
- `/settings/privacy`：私信权限和在线状态设置。
- App Shell 私信入口：展示私信未读数，不混入通知 Bell。
- 用户主页和 hover card 的“私信”动作。
- 帖子、评论、用户、社区分享菜单里的“发送给好友”。
- 陌生人消息入口、请求列表、请求详情、接受、忽略、举报、拉黑。
- 文字、图片、帖子分享卡片、评论分享卡片、用户分享卡片、社区分享卡片。
- WebSocket 即时到达和断线补偿。

### 不做

- 不做语音消息。
- 不做视频消息。
- 不做语音通话、视频通话。
- 不显示“已读”“对方已读”“已送达”。
- 不做邮箱式分类页。
- 不在主界面暴露 `all/friends/requests/archived` tabs。
- 不把陌生人请求当作普通待办审批流展示。
- 不把后端未返回的能力伪造成可用。

## 3. 路由和页面职责

### `/messages`

默认进入私信主界面。桌面端如果已有会话，选中最近一条会话并展示右侧聊天线程；如果没有会话，右侧展示极简空状态。

移动端先展示会话列表；点击会话后进入聊天线程，左上角提供返回列表。

### `/messages/[conversationId]`

直接打开指定会话。桌面端左侧列表仍然可见，指定会话高亮；移动端直接进入聊天线程。

### `/messages/requests`

陌生人消息页。它不是顶部 tab，而是由左侧列表中的“陌生人消息”入口进入。入口只在存在待处理或历史陌生人请求时出现。

### `/settings/privacy`

只承载私信权限、陌生人消息、在线状态等设置。不要把这些设置塞进聊天主界面。

## 4. 桌面端界面骨架

### 画布

以 1920px 宽桌面为主要验收视口，整体接近用户截图：

| 区域 | 尺寸 / 行为 |
| --- | --- |
| 私信页面高度 | 占满 App Shell 可用高度 |
| 左侧会话栏 | 240px 到 260px 固定宽度 |
| 右侧聊天区 | 剩余宽度全占满 |
| 顶部聊天 header | 44px 到 48px 高 |
| 底部输入栏 | 36px 到 44px 高，贴近聊天区底部 |
| 分割线 | 1px，低对比 |
| 主背景 | 深灰蓝黑，不能是纯黑大面积死板底色 |
| 列表选中态 | 中性灰块，不用品牌色铺满 |

### 左侧会话栏

结构只能是：

1. 搜索框。
2. 会话列表。

不能在搜索框下面加 `全部 / 朋友 / 陌生人 / 归档`。抖音 PC 私信主界面没有这种邮箱式筛选区，本项目也不做。

搜索框：

- placeholder 使用 `搜索`。
- 高度约 28px。
- 左侧搜索图标。
- 输入后只过滤当前会话和用户结果，不改变主界面结构。
- 不显示“搜索私信”这种冗长文案。

会话行：

| 元素 | 规格 |
| --- | --- |
| 行高 | 52px 到 58px |
| 头像 | 38px 到 44px 圆形 |
| 昵称 | 单行，13px 到 14px，半粗 |
| 预览 | 单行，12px，低对比 |
| 时间 | 右上角 11px 到 12px |
| 未读 | 右侧红点或小红 badge |
| 在线 | 只在允许显示时用小绿点或短文本 |
| 选中态 | 整行灰色背景 |

预览文案规则：

| 消息状态 | 预览 |
| --- | --- |
| 文字 | 最后一条文本截断 |
| 图片 | `[图片]` |
| 帖子分享 | `分享[帖子]` |
| 评论分享 | `分享[评论]` |
| 用户分享 | `分享[用户]` |
| 社区分享 | `分享[社区]` |
| 自己发出的陌生人请求 | `等待对方通过` 或最后一条首条消息 |
| 收到的陌生人请求 | `发来一条陌生人消息` |
| 撤回 | `撤回了一条消息` 或 `你撤回了一条消息` |
| 图片审核失败 | `图片审核失败` |
| 被拉黑 / 已拉黑 | `无法继续发送消息` |

### 右侧聊天 header

左侧显示：

- 对方头像。
- 对方昵称。
- 可选在线状态：如 `2分钟前在线`。只有双方互关且双方都开启在线状态时显示。

右侧只显示更多菜单按钮。更多菜单内放：

- 置顶 / 取消置顶。
- 免打扰 / 取消免打扰。
- 归档。
- 删除本地会话。
- 举报。
- 拉黑 / 取消拉黑。

实现边界：当前后端已接通置顶 / 取消置顶、免打扰 / 取消免打扰、归档 / 取消归档、删除本地会话、举报会话、拉黑 / 解除拉黑，以及单条消息举报、撤回和删除。前端更多菜单必须全部走真实端点。

不要在 header 里堆主按钮，不要显示“会话信息面板”式右栏。

### 聊天区

聊天区是右侧主体，不加卡片容器，不加圆角大边框。

消息排列：

- 对方消息靠左，自己的消息靠右。
- 对方消息显示头像，自己的消息显示头像。
- 自己的文字气泡使用明亮蓝色。
- 对方文字气泡使用中性灰。
- 气泡圆角克制，贴近截图，不能做成夸张胶囊。
- 单条文字气泡最大宽度约 420px；长文本自动换行。
- 图片消息按原比例展示，最大宽度 280px 到 360px。
- 时间分割居中，小字号低对比。
- 系统提示居中，例如 `对方接受了你的私信请求`。
- 分享提示可使用轻量强调色，例如 `对方 分享了帖子`，但不能大面积高亮。

禁止：

- 不做邮件阅读面板。
- 不做整屏圆角卡片。
- 不做消息卡片套卡片。
- 不在消息中显示“已读”。
- 不把陌生人请求操作放到自己发出的请求里。

### 输入栏

输入栏固定在聊天区底部。

内容：

- 左侧文本输入，placeholder `发送消息`。
- 右侧图标按钮：表情、图片、更多或发送。
- 不出现麦克风、电话、摄像机。
- Enter 发送，Shift + Enter 换行。
- 发送中禁用重复提交。

禁用态：

| 场景 | 输入区表现 |
| --- | --- |
| 我发出的陌生人请求未通过 | 可输入；点击发送失败，提示 `发送失败：对方通过前不能继续发送。` |
| 我收到的陌生人请求未处理 | 可输入；点击发送失败，提示 `发送失败：接受陌生人消息后才能回复。`，并显示接受 / 忽略动作 |
| 已拉黑对方 | 禁用，提示 `你已拉黑对方，无法发送消息` |
| 被对方拉黑 | 禁用，提示 `暂时无法发送消息` |
| 对方账号封禁 / 注销 / 删除 | 禁用，提示 `对方账号不可用` |
| 我的账号被禁言或封禁 | 禁用，提示后端返回原因 |
| 后端限流 | 保留输入内容，显示错误，允许稍后重试 |

## 5. 移动端适配

移动端不强行保留左右两栏：

- `/messages` 展示会话列表。
- 点击会话进入 `/messages/[conversationId]`。
- 聊天页顶部显示返回箭头、头像、昵称、在线状态、更多菜单。
- 输入栏固定底部，避开安全区。
- 陌生人消息入口仍是会话列表中的一行，不是 tab。

移动端可以更像 App，但仍不复制第三方品牌素材。

## 6. 陌生人消息机制

### 基本模型

用户关系分为：

- `self`：自己，不能给自己私信。
- `mutual`：互关，可以直接发私信。
- `following`：我关注对方但对方未关注我，按对方隐私设置决定是否需要请求。
- `followed_by`：对方关注我但我未关注对方，按我的隐私设置决定是否需要请求。
- `none`：无关系，通常进入陌生人请求。

首版规则：

- 互关直接进入普通会话。
- 非互关先进入陌生人请求。
- 请求未接受前，发起人只能发送首条文字或分享卡片。
- 请求未接受前，发起人不能连续追发。
- 请求未接受前，收件人不能直接聊天，只能接受、忽略、举报或拉黑。
- 接受后转为普通会话，双方可继续聊天。
- 忽略 / 删除后请求从收件人陌生人列表移除。
- 举报后按有限上下文提交审核。
- 拉黑后双方不能继续发送，历史消息保留。

### 发给我的陌生人请求

只要请求方向是 `incoming`，也就是对方发给我，界面才显示处理动作。

入口：

- 左侧列表中出现 `陌生人消息` 行。
- 行内显示未处理数量。
- 点击进入陌生人请求列表或直接打开最新请求。

请求列表行：

- 对方头像。
- 昵称。
- 首条消息预览。
- 时间。
- 未处理红点。

请求详情：

- 顶部显示对方信息。
- 展示对方首条消息或分享卡片。
- 底部不是普通输入框，而是动作区。
- 主动作：`接受`。
- 次动作：`忽略`。
- 更多动作：`举报`、`拉黑`。

接受后：

- 请求状态变为普通会话。
- 输入栏恢复。
- 会话进入普通会话列表。
- 系统提示 `已接受私信请求`。

忽略后：

- 请求从陌生人消息列表消失。
- 不通知发起人具体结果。
- 发起人侧仍只看到等待或不可继续发送的状态，具体由后端策略决定。

### 我发出的陌生人请求

请求方向是 `outgoing` 时，绝对不能显示 `接受`、`忽略`、`批准`、`通过` 等处理动作。

发起人侧表现：

- 会话列表可以出现该会话。
- 预览显示 `等待对方通过`，或展示自己发出的首条内容。
- 聊天详情展示自己发出的首条消息。
- 底部输入栏禁用，提示 `等待对方通过后可继续聊天`。
- 更多菜单可以保留删除本地会话、举报、拉黑，但不能有接受/忽略。

如果对方接受：

- WebSocket 或下一次 HTTP 刷新把会话切为普通会话。
- 输入栏恢复。
- 可显示系统提示 `对方已接受你的私信请求`。

如果对方忽略：

- 不展示“对方拒绝了你”这种强反馈。
- 可以继续保持等待态，或后端返回 `request_rejected` 后隐藏会话 / 禁止继续发送。

### 为什么必须有请求方向字段

只靠 `request_status=pending` 会导致前端犯严重错误：自己发出的请求也可能被渲染成“待我处理”，于是出现“我私信别人，我这里显示批准陌生人信息”的错误。

前端必须以后端返回的方向字段作为动作显示依据：

```text
request_direction=none|incoming|outgoing
viewer_can_accept_request=true|false
viewer_can_reject_request=true|false
```

显示规则：

| request_direction | viewer_can_accept_request | UI |
| --- | --- | --- |
| incoming | true | 显示接受 / 忽略 |
| incoming | false | 显示只读请求状态 |
| outgoing | false | 显示等待对方通过，不显示处理动作 |
| none | false | 普通会话，不显示请求动作 |

在后端字段补齐前，前端宁可隐藏接受/忽略，也不能把 pending 请求错误展示给发起人处理。

## 7. 会话列表规则

会话列表的排序由后端权威数据决定：

1. 置顶会话。
2. 最近消息或最近事件时间。
3. 陌生人消息入口按最新请求时间参与排序，或固定在列表靠上位置。

会话行只负责快速进入聊天，不承载管理界面。

### 不显示的东西

主会话列表不显示：

- `全部` tab。
- `朋友` tab。
- `陌生人` tab。
- `归档` tab。
- 批量管理模式。
- 后台式筛选器。
- 已读 / 未读筛选。

需要搜索时用顶部搜索框；需要归档时从更多菜单进入，不抢主流程。

### 陌生人消息入口

陌生人消息不是 tab，而是一条特殊会话入口：

```text
陌生人消息
3 条待处理
```

展示条件：

- 有 incoming pending 请求时必须展示。
- 有历史请求但无待处理时可以展示低优先入口。
- 完全没有陌生人请求时不展示。

## 8. 消息类型

### 文字

- 支持多行。
- 发送前 trim 只用于判断空消息，不破坏用户换行。
- 过短高频、重复文本、联系方式刷屏由后端风控处理。

### 图片

- 复用现有上传能力。
- 发送前显示本地预览和发送中状态。
- 发送失败可重试。
- 审核失败显示 `图片审核失败`，不展示原图。

### 分享卡片

支持：

- 帖子分享卡片。
- 评论分享卡片。
- 用户分享卡片。
- 社区分享卡片。

卡片必须保存快照字段：

| 字段 | 用途 |
| --- | --- |
| `share_type` | `post/comment/user/community` |
| `share_id` | 原始资源 ID |
| `title` | 发送时标题快照 |
| `summary` | 发送时摘要快照 |
| `thumbnail_url` | 发送时缩略图快照 |
| `target_url` | 发送时目标 URL 快照 |
| `snapshot_created_at` | 快照时间 |

视觉规格：

- 卡片在气泡内或紧贴气泡展示。
- 宽度约 260px 到 320px。
- 左侧或上方缩略图，右侧 / 下方标题和摘要。
- 标题最多两行。
- 摘要最多两行。
- 类型标记使用小字，不用大 badge。

降级规则：

- 原内容删除、不可见、审核下架或权限不足时，卡片显示 `内容暂不可查看`。
- 仍保留发送时快照里的类型和时间。
- 不跳转到不可访问页面。

## 9. 消息状态

| 状态 | UI |
| --- | --- |
| sending | 气泡旁小型进度状态 |
| sent | 不额外显示 |
| failed | 气泡旁显示失败图标，可重试 |
| recalled_by_me | `你撤回了一条消息` |
| recalled_by_peer | `对方撤回了一条消息` |
| deleted_local | 本地隐藏，不影响对方 |
| invisible | `消息暂不可见` |
| reviewing | `审核中` 或 `仅自己可见` |
| image_rejected | `图片审核失败` |
| blocked | 输入区禁用 |
| rate_limited | 保留输入，提示稍后再试 |

不显示：

- `已读`。
- `未读` 的单条状态。
- `已送达`。
- 对方正在输入，除非后端明确提供且产品重新确认。

## 10. 私信设置

设置页使用普通设置结构，不进入聊天主界面。

### 谁可以给我发私信

后端首版字段：

```text
allow_messages=everyone|mutuals|none
```

前端文案：

| 值 | 文案 |
| --- | --- |
| everyone | 所有人 |
| mutuals | 互相关注的人 |
| none | 不接收私信 |

如果后端未来扩展更接近抖音的细粒度设置，可以增加：

- 我关注的人。
- 互相关注的人。
- 可能认识的人。
- 陌生人消息请求。

这些不能在后端没有字段时提前展示成可用开关。

### 在线状态

默认关闭。

显示条件必须同时满足：

1. 我开启在线状态。
2. 对方开启在线状态。
3. 双方互关。
4. 后端返回 `peer_online_status_visible=true`。

关闭在线状态后：

- 别人看不到我在线。
- 我也不能看别人在线。

### 已读状态

不提供用户设置，因为产品层不显示已读。后端 read cursor 只用于未读数和打开会话后清未读。

## 11. 用户入口和分享入口

### 用户主页 / Hover Card

私信动作显示规则：

| `dm_capability` | UI |
| --- | --- |
| `can_start=true` and `direct_conversation_id` exists | 点击进入既有会话 |
| `can_start=true` and `requires_request=false` | 点击创建普通会话 |
| `can_start=true` and `requires_request=true` | 点击打开首条请求输入 |
| `can_start=false` | 显示禁用态和后端原因 |

禁用原因必须使用后端返回值映射中文，不要臆造：

- 自己。
- 对方关闭私信。
- 你已拉黑对方。
- 对方不可用。
- 账号受限。

### 发送给好友

帖子、评论、用户、社区的分享菜单增加 `发送给好友`。

会话选择器：

- 搜索好友和已有会话。
- 优先显示最近互关会话。
- 可发送给已有普通会话。
- 发送给非互关用户时走陌生人请求首条分享卡片。
- 如果对该用户已有 pending outgoing 请求，禁止重复发送并提示 `等待对方通过后可继续聊天`。

会话选择器不是主私信页面，不复用邮箱式列表。

## 12. 实时策略

HTTP 是权威数据源，WebSocket 只做增量事件。

WebSocket ticket：

```text
POST /api/v1/realtime/tickets
ws   /api/v1/realtime/messages?ticket=...
```

事件类型：

- 新消息。
- 消息撤回。
- 会话摘要更新。
- 未读数更新。
- 请求接受。
- 请求拒绝 / 忽略。
- 拉黑状态变化。
- 在线状态变化，如果后端支持。

客户端规则：

- 记录最后处理的 `event_id`。
- 按 `event_id` 去重。
- 断线自动重连。
- 重连后用 HTTP 按 `last_event_id` 或会话更新时间补齐。
- WebSocket 到达的消息可先插入本地，但下一次 HTTP 返回为准。

## 13. 治理和风控

### 陌生人限流

非互关首条请求需要限流：

- 同一发起人短时间大量请求返回 `rate_limited`。
- 同一收件人短时间收到大量请求可触发后端风控。
- 重复文本、联系方式刷屏、明显广告进入失败或审核中状态。

### 举报

举报私信时提交：

- 被举报消息。
- 前后有限上下文。
- 会话参与者。
- 分享卡片或图片快照。
- 举报原因。

审核后台不能任意浏览未举报私信。只有被举报消息及有限上下文进入审核可见范围。

### 拉黑

拉黑后：

- 双方不能继续发送。
- 历史会话保留。
- 输入区禁用。
- 对方不应获得过强反馈，只显示不可发送或发送失败。

### 账号不可用

以下状态必须禁发：

- 我的账号封禁。
- 我的账号禁言。
- 对方账号封禁。
- 对方账号注销。
- 对方账号软删除。

## 14. 后端合同要求

已有后端合同按 `backend-api-needs.md` 的 `2.8 READY` 接入。为了避免陌生人请求方向错误，conversation response 还必须补充这些字段：

```json
{
  "request_direction": "none|incoming|outgoing",
  "viewer_can_accept_request": false,
  "viewer_can_reject_request": false
}
```

推荐同时补充：

```json
{
  "request_created_by_me": true,
  "request_to_me": false,
  "conversation_state": "normal|incoming_request|outgoing_request|blocked|disabled"
}
```

字段语义：

| 字段 | 必需 | 用途 |
| --- | --- | --- |
| `request_direction` | 必需 | 决定是否显示陌生人请求动作 |
| `viewer_can_accept_request` | 必需 | 防止前端误判 |
| `viewer_can_reject_request` | 必需 | 防止前端误判 |
| `request_created_by_me` | 可选 | 调试和文案辅助 |
| `request_to_me` | 可选 | 调试和文案辅助 |
| `conversation_state` | 推荐 | 统一禁用输入区原因 |

后端现有 `box=requests` 可以继续只返回发给我的 pending 请求；但普通会话列表中如果包含我发出的 pending 请求，也必须显式返回 `request_direction=outgoing`。

## 17. 验收标准

### 界面

- 1920px 桌面端首屏是左侧会话列表 + 右侧聊天线程。
- 左侧顶部只有搜索框，没有 `全部 / 朋友 / 陌生人 / 归档` tabs。
- 会话列表是线性行，不是邮箱式管理表，不是后台工单。
- 选中行是灰色块。
- 右侧 header 显示头像、昵称、可选在线状态、更多按钮。
- 聊天区左右气泡、图片和分享卡片位置符合截图骨架。
- 底部输入栏贴底，placeholder 为 `发送消息`。
- 没有语音、视频、通话入口。
- 没有用户可见“已读”。

### 陌生人请求

- 非互关只能发一条请求。
- 我发出的请求显示等待状态，不能出现接受、忽略、批准。
- 发给我的请求才显示接受、忽略、举报、拉黑。
- 接受后转普通会话。
- 忽略后不强通知发起人。
- 拉黑后双方禁发。

### 分享卡片

- 帖子、评论、用户、社区都能生成分享卡片。
- 卡片含类型、标题、摘要、缩略图和目标 URL 快照。
- 原内容删除或不可见时降级为 `内容暂不可查看`。

### 实时

- WebSocket 新消息即时插入。
- 断线重连后不丢消息。
- 重连补偿后不重复显示。
- 请求接受、撤回、拉黑状态可以实时刷新或通过补偿刷新。

### 隐私和风控

- 在线状态默认关闭。
- 开启后仅互关且双方开启时可见。
- 举报只提交有限上下文。
- 审核端不能任意浏览未举报私信。
- 账号封禁、注销、软删除都禁发。
